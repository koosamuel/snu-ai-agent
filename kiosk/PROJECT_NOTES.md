# 카페 키오스크 작업 노트

최종 갱신: 2026-10-12

## 1. 목표

- 고객은 태블릿에서 메뉴와 옵션을 선택하고 주문번호를 받는다.
- 운영자는 로그인 후 주문 상태를 실시간으로 변경한다.
- 별도 상시 운영 서버 없이 GitHub Pages와 Supabase를 사용한다.

## 2. 결정한 구조

- 프런트엔드: 빌드가 필요 없는 HTML·CSS·JavaScript 정적 사이트
- 호스팅: GitHub Pages를 기본 배포 대상으로 사용
- 백엔드: Supabase Postgres·Auth·Realtime
- 주문 생성: 공개 테이블 INSERT가 아니라 `create_kiosk_order` RPC로 처리
- 가격 검증: 메뉴와 옵션 가격을 서버에서 재조회해 계산
- 주문 도우미: 박우진 교수님 RAG 키오스크의 검색·의도 분류·결정적 검증 구조를 정적 클라이언트에 맞게 적용
- AI 보안 경계: 브라우저는 현재 메뉴 문서만 검색하며 생성형 모델 비밀 키는 넣지 않음
- 오프라인: 화면·메뉴 샘플은 캐시하되 실제 주문은 네트워크 연결이 필요
- 결제: 카드·카운터 결제 요청만 기록하며 실제 승인은 구현 범위에서 제외

## 3. 구현 범위

- 고객: 분류, 검색, 옵션, 수량, 장바구니, 포장/매장, 주문 접수
- 주문 도우미: 자연어 메뉴 검색, 취향 추천, 두 메뉴 비교, 가격·장바구니 조회, 기본 옵션 담기·빼기
- 운영자: 로그인, 실시간 주문판, 상태 변경
- 데이터: 메뉴·옵션·주문·주문 항목·운영자 프로필
- 보안: 공개 메뉴 읽기와 운영자 권한을 RLS로 분리
- 배포: 상대 경로, PWA manifest, service worker, 정적 빌드 스크립트

## 4. 다음 단계

1. 별도 Supabase 프로젝트를 생성하고 스키마를 적용한다.
2. 운영자 계정을 등록하고 RLS를 실제 계정으로 검증한다.
3. 실제 카페 메뉴와 가격으로 샘플 데이터를 교체한다.
4. 생성형 RAG가 필요하면 Supabase Edge Function 또는 별도 Worker를 선택하고 서버 측 메뉴·가격 검증 계약을 정의한다.
5. 행사장 태블릿과 운영자 기기에서 동시 주문을 시험한다.
6. 실제 결제가 필요하면 결제 단말 업체와 연동 범위를 정한다.
